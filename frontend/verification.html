Verification steps

1. Original defect reproduction steps

The original defect: a promotion registered with two rule rows for the same tenant and channel — one SKU-specific, one channel-wildcard — was applied twice, giving the customer the same discount twice.

  1. Open the application at /index.html.
  2. Navigate to the Promotions page.
  3. Register a promotion with id promo-repro:
    • Type: percent, Value: 10, Channel: web, SKU: SKU-00001, Priority: 5
    • Valid from: 2026-01-01, Valid until: 2027-01-01
  4. Register the SAME promotion id promo-repro again with SKU empty (wildcard rule row).
  5. Navigate to the Pricing simulator page.
  6. Submit a quote for SKU SKU-00001, channel web, quantity 1.
  7. Before the fix: promo-repro appears twice in applied_promotion_ids and the discount is applied twice.
  8. After the fix: promo-repro appears exactly once in applied_promotion_ids and the discount is applied once.

2. Corrected-behaviour verification steps

  1. Open the application at /index.html.
  2. Navigate to the Pricing simulator page.
  3. Submit a quote for SKU SKU-00001, channel web, quantity 1.
  4. Verify the response shows the expected final yen (e.g. 900 for a 10% discount on a 1000-yen base).
  5. Verify applied_promotion_ids contains each promotion id exactly once.
  6. Navigate to the Batch dashboard page.
  7. Submit a batch with the same SKU and channel.
  8. Verify the batch result agrees with the interactive result (same final yen).
  9. Navigate to the Audit viewer page.
  10. Verify that a promotion.applied audit event was recorded for the quote.

3. Manual-override feature verification steps

  1. Open the application at /index.html.
  2. Navigate to the Manual overrides page.
  3. Verify the page shows tenant tenant-a with feature enabled and threshold JPY 3,000,000.
  4. Test: two approvals above threshold.
    1. Set Override ¥ to 3,500,000 and enter a reason.
    2. Click "Create override request". Verify status is "pending" and required approvals is 2.
    3. As approver tenant-a-approver, enter a reason and click "Approve". Verify status is still "pending" (1/2).
    4. As admin tenant-a-admin, enter a reason and click "Approve". Verify status is "approved" (2/2).
    5. Click "Apply". Verify status is "applied".
  5. Test: requester cannot approve own request.
    1. Create a new override request as tenant-a-requester.
    2. As the same requester, try to approve. Verify an error message appears.
  6. Test: approval reason is mandatory.
    1. Create a new override request.
    2. As approver, click "Approve" without entering a reason. Verify an error message appears.
  7. Test: one approval below threshold.
    1. Set Override ¥ to 500 (below the 3,000,000 threshold).
    2. Create the request. Verify required approvals is 1.
    3. As approver, approve once. Verify status is "approved" (1/1).
  8. Navigate to the Evidence dashboard to see the full audit trail.
